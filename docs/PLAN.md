# Планер Миланы — ТЗ и решения

Личный PWA-планер для одного пользователя. Вход по почте, синхронизация телефон ↔ компьютер,
интерфейс на русском, mobile-first, на широком экране неделя целиком.

Сферы жизни: работа в MIMAY, администратор в онлайн-школе английского, учёба (журналистика, заочно),
тренировки, языки (испанский, английский, турецкий), личное.
Без помодоро и принудительных циклов.

## Принятые решения

- Отдельный репозиторий `planner-milana` (старый `-speakify` не трогаем).
- Стек: React + Vite + TypeScript, PWA, offline-first.
  - Локальная база Dexie (IndexedDB) — источник правды; облако — только синхронизация.
  - Слой данных за интерфейсом-адаптером, бэкенд заменяемый.
  - Основной кандидат — Supabase (auth, БД с RLS, storage). Запасной — PocketBase на российском VPS
    (Timeweb/Selectel, ~200–400 ₽/мес). Выбор — по результатам `check/`.
  - Хостинг: GitHub Pages (проверяется страницей `check/`).
- Вход по 6-значному коду из письма (OTP), не magic link (на iPhone ссылка открывается в Safari, а не в PWA).
  Регистрация для чужих закрыта, RLS — доступ только владельцу. Секретные ключи в код не кладём
  (в браузере только публичный anon-ключ, защита — через RLS).
- Телефон: iPhone (iOS 27). Web push работает только в PWA, установленной на экран «Домой»,
  и требует сервера-отправителя.
- Неделя начинается с понедельника.
- Просроченные задачи остаются на своём дне до вечернего разбора; автоматически ничего не переносится.
- «Последний рабочий день месяца» = последний будний день (Пн–Пт), праздники не учитываются.
- Привычки — только галочки, без чисел.
- Шкала часов в виде «День» настраивается (с какого по какой час).
- Категории внутри дня: у каждого дня свой набор, названия вводятся вручную («+ категория»),
  можно переименовать/удалить, перетаскивать задачи между категориями; задачи без категории — сверху.
  Внутри категории: без времени — списком, со временем — по времени. Это отдельно от «сфер» (цветных меток).

## Функции

1. **Задачи**: название, дата или без даты, время начала/конца (необязательно), сфера, заметка, «сделано»,
   повторы (каждый день; по дням недели; раз в N недель; раз в месяц — число или «последний будний день»),
   напоминание (push, только если включено), необязательный таймер старт/стоп.
2. **«Неделя»** (главный экран): «Фокус недели» (2–3 цели + мудборд); 7 дней с категориями, задачами,
   заметкой дня, привычками; drag & drop между днями (и на телефоне); листание недель.
3. **«День»**: выбор даты, задачи без времени списком, со временем — на шкале часов, заметка, привычки, стикеры;
   можно сделать стартовым экраном.
4. **«Когда-нибудь»**: задачи без даты, назначить/перетащить на день.
5. **Привычки**: свои, с днями недели; галочки; видны в неделе и дне; статистика за неделю/месяц.
6. **Вечерний разбор**: время настраивается; по каждой невыполненной — на завтра / на другой день /
   в «Когда-нибудь» / удалить.
7. **Планирование недели**: день настраивается; шаг 1 — итоги прошлой недели; шаг 2 — фокус, цели, мудборд;
   шаг 3 — раскидать «Когда-нибудь» и невыполненное по дням.

## Этапы

0. Проверка доступности сервисов (`check/`) + стиль (выбран «Шалфей»).
1. Каркас: проект, вход по коду, база, PWA, деплой, offline-first основа.
2. Задачи, сферы, категории дня, «Неделя», «День», «Когда-нибудь».
3. Повторы, привычки.
4. Вечерний разбор, планирование недели.
5. Темы (пастельные + своя), свои SVG-стикеры + загрузка PNG, мудборд.
6. Напоминания, таймер, полировка офлайн-синхронизации.

## Как устроено (этап 1)

- Публикация: GitHub Actions (`.github/workflows/deploy.yml`) собирает сайт при каждом пуше в `main`
  и выкладывает на https://milanaabdulgazizova-ctrl.github.io/planner-milana/ (Settings → Pages → Source: GitHub Actions).
- Страница проверки сервисов: `public/check/index.html` → `/planner-milana/check/`.
- База в облаке: одна таблица `records` (id, kind, data jsonb, updated_at, deleted, server_updated_at), RLS «только своё»,
  удаления мягкие. Скрипт: `supabase/setup.sql`. Новые виды данных не требуют менять базу.
- Локально: Dexie (`src/data/db.ts`), у каждой записи `updatedAt`, `deleted`, `dirty`.
- Синхронизация (`src/data/sync.ts`): отправить изменённое (`dirty`) → скачать новое по `server_updated_at`;
  конфликт — побеждает более позднее изменение (и на устройстве, и на сервере через триггер).
- Облако за интерфейсом `Backend` (`src/data/backend.ts`), реализация — `supabaseBackend.ts`.
- Вход: код из письма, `shouldCreateUser: false` — новых пользователей приложение не создаёт;
  владелец добавлен вручную в Supabase, регистрация выключена.

## Настройки Supabase (сделаны вручную, 04.11.2026)

- База создана скриптом `supabase/setup.sql`.
- Владелец добавлен вручную (Authentication → Users), регистрация новых пользователей выключена.
- Письма отправляются через SMTP Яндекс Почты (smtp.yandex.ru:465, пароль приложения хранится только в Supabase):
  встроенная почта Supabase не позволяет менять шаблоны.
- Шаблон «Magic link or OTP»: тема «Код для входа в планер», тело `<p>Ваш код для входа: <b>{{ .Token }}</b></p>`.
- GitHub Pages: Source = GitHub Actions.
- Этап 1 проверен: вход по коду работает (04.11.2026).

## Этап 2 (сделано, версия 0.2.0)

- Задачи: время начала/конца, сфера, заметка, категория дня; окно редактирования по нажатию на задачу.
  Быстрый ввод: «10:00 Созвон» или «10:00-11:30 Созвон» сразу ставит время.
- Сферы: 6 стандартных (постоянные id через `uuidFrom`, чтобы не было дублей между устройствами), редактируются в Настройках.
- Категории дня: «+ категория», переименование (нажать на название), удаление (задачи остаются без категории).
- «Неделя»: фокус недели (до 3 целей), блок «Когда-нибудь», 7 дней с категориями и заметкой дня.
- «День»: задачи без времени по категориям, шкала часов (часы — в Настройках), заметка.
- Перетаскивание (@dnd-kit/core): мышью; на телефоне — зажать ~0,3 с и тянуть. Между днями, категориями, из/в «Когда-нибудь».
- Стартовый экран (Неделя/День) — в Настройках. Настройки синхронизируются между устройствами.
- Цвет фона (0.2.1): 8 готовых пастельных + свой цвет; хранится в настройках (синхронизируется), локальная копия — чтобы не мигало при запуске.

## Этап 3 (сделано, версия 0.3.0)

- Повторы (`src/lib/repeat.ts`): каждый день; по дням недели + каждую N-ю неделю; раз в месяц — число
  (если числа нет в месяце — последний день) или последний будний день.
- Устройство: задача с `repeat` — шаблон серии (не показывается). Копии на дни считаются «на лету»;
  при первом действии (галочка, перенос, правка) копия записывается в базу с постоянным id
  `uuidFrom('occ:' + seriesId + ':' + date)` — два устройства не создают дублей.
  Поля копии: `seriesId`, `occurrenceDate`, `skipped` (удалена «только этот раз»).
- Правка копии: «Только этот раз» / «Все повторы» (меняет шаблон и невыполненные копии с этой даты).
  Удаление: «Только этот раз» / «Этот и все следующие» (шаблону ставится `until`).
  «Повтор: нет» на копии — эта копия становится обычной задачей, следующие убираются.
- Привычки: вкладка «Привычки» (название, дни недели, статистика неделя/месяц, точки за месяц);
  галочки в «Неделе» и «Дне». Отметка = запись `habitCheck` с id `uuidFrom('habit:' + habitId + ':' + date)`.
  Статистика считается с даты создания привычки, будущие дни не учитываются.

## Этап 4 (сделано, версия 0.4.0)

- Настройки: время вечернего разбора (по умолчанию 21:00), день планирования (по умолчанию вс).
  Отметки «последний разбор» и «последняя спланированная неделя» хранятся в настройках (синхронизируются).
- Вечерний разбор (`ReviewSheet`): после заданного времени на «Неделе»/«Дне» появляется баннер.
  Список: обычные невыполненные задачи с датой ≤ сегодня (все), копии повторов — с прошлого разбора, не больше 7 дней.
  Действия: Сделано / На завтра / Другой день / Когда-нибудь (не для повторов) / Удалить (для повторов — Пропустить).
  Само ничего не переносится.
- Планирование недели (`PlanningWizard`): баннер в день планирования и на следующий день, если неделя ещё не спланирована;
  также кнопка «Спланировать» на «Неделе» (планирует показанную неделю) и в Настройках.
  Планируемая неделя: если день планирования — понедельник, текущая; иначе следующая.
  Шаги: 1) итоги прошлой недели (выполнено, по сферам, привычки, фокус); 2) фокус и цели;
  3) раскидать «Когда-нибудь» и невыполненное по дням нажатием на день.

## Этап 5 (сделано, версия 0.5.0)

- Темы: 8 готовых пар «фон + акцент» и своя (фон и акцент — из палитры или любой цвет).
  `--line`, `--soft`, `--today` вычисляются из фона и акцента (color-mix), поэтому любая тема цельная.
- Картинки: запись `asset` (путь, размер) синхронизируется как обычно; сам файл хранится локально (таблица `blobs`)
  и в Supabase Storage (бакет `planner`, папка = id пользователя, RLS — только своя папка; скрипт `supabase/storage.sql`).
  Загрузка в облако — в общем цикле синхронизации (`syncBlobs`), скачивание — по требованию при показе.
  Перед сохранением картинки уменьшаются: стикеры до 400 px (PNG), фото до 1400 px (JPEG).
- Стикеры: 20 своих SVG (`src/lib/stickers.ts`) + загруженные PNG. Добавляются в «Дне» (нажать — убрать), в «Неделе» видны рядом с днём.
- Мудборд: картинки к фокусу недели (на «Неделе» и в шаге 2 планирования), коллаж с лёгким наклоном.
